# 提示词优化与产品迭代反馈对应表

本次将 `feature/prompt-optimization` 分支提交 `db375fb` 中的同伴提示词表达层移入 `main`。移入前 `main` 的基线为 `e20866c`，使用 DeepSeek；表达层与模型无关，沿用 main 的模型、流式思考、账号、故事保存和界面实现。

Claude 多轮评估 pipeline 继续保留在 `feature/prompt-optimization`。本次 main 仅接入表达层、对应测试与本说明。

## 已采用的反馈

| 反馈位置与内容 | 具体优化 | 实现位置 |
|---|---|---|
| 第一节：零负担陪伴；无条件接纳，尊重暂不行动 | 先回应当前感受或目标；不劝振作，不把行动当成勇敢证明；允许沉默、停下与暂不行动 | `empathy` |
| 2.2：回复太长、掉书袋、阅读困难 | 默认100—200字、最多300字；激动或看不进去时尽量50—100字；用户要求详说时可放宽 | `pacing`、`continuity` |
| 2.2：每轮最多一个问题、两个动作，只推进一个方向 | 明确问题与动作上限；“要不要展开”也占问题名额；信息够用就回应，不为流程追问 | `pacing` |
| 2.2：先给重点，再逐步展开 | 复杂内容先给概要，展开当前第一步；按用户请求继续说明 | `pacing` |
| 2.2：收尾三选一；倾诉时不要急于建议 | 轻量问题、行动邀请、确认感受只选一个；倾诉优先确认感受，不强行询问是否要建议 | `expression` |
| 2.2：像真人聊天、更温暖，但角色幻觉需要限制 | 用自然日常表达承接具体感受；保持AI身份，不虚构“我也经历过”，不把匿名案例说成自己的故事 | `empathy`、`expression`及固定边界 |
| 2.2：纯对话体、少格式；2.3：出现英文词 | 普通陪伴用自然简体中文、短句和空行；不用标题、表格、加粗、符号列表或装饰表情；避免不必要英文和术语 | `expression` |
| 2.2：禁用“你值得被好好对待”等翻译腔 | 普通回复不使用该句，也不用“我完全懂你”“我也经历过”等表达 | `expression` |
| 2.1：多轮回答不一致；2.2：根据已经了解的情况回应 | 回答最新一句、沿用用户已明确说明的事实与偏好；不重复盘问；不把助手推断当事实；误解后简短承认和更正 | `continuity` |
| 2.2：不复述姓名、电话、地址 | 避免复述用户姓名、电话、住址、账号等身份信息，必要时用称谓或隐藏占位符；公共支持热线除外 | 固定边界 |
| 2.2：安全窗口受限时优先关键信息 | 用户只剩几分钟或有现实人身危险时，一次给出最必要安全信息，可不提问、放宽字数与动作数；事实、隐私和安全边界继续适用 | 固定边界 |

上述四个字段位于 [提示词JSON](../prompts/companion-style.json)，固定边界位于 [表达层构建代码](../lib/companion-style.ts)。这次采用的是提示词约束，不是对每次输出长度、问题数或行为的确定性保证。

## 保留与范围边界

| 反馈内容 | 本次处理 |
|---|---|
| 2.1、2.2中法律条件、机关行动、绝对化词汇、现实预警、检索为空等法律规则 | 按本次明确要求，法律提示词、SOP文本、检索逻辑、法条与现有法律验收标准均不修改；保留原有SOP为空时的处理 |
| 普通对话字数与格式可能妨碍法律信息完整性 | 法律咨询、SOP转述、维权步骤沿用原有规则与格式；不得为字数或动作限制删去必需的法条、条件、时效与限定语 |
| 危机固定回复含有普通场景禁用语 | 危机固定回复原文保留，优先于字数、格式与禁用语限制 |
| “我懂你的感受，我也经历过”及故事分享 | 采用温暖语气，不采用虚构亲历；没有上线新故事或改动嘉宾对话 |
| “不会使用用户数据训练模型” | 不新增尚未核实的数据政策承诺；原有隐私规则保持不变 |
| 人工转接、总结邮件、自动下架等 | 未新增这些能力；提示词禁止声称已经完成尚未执行的操作 |
| 卡住、多轮不返回；下载、保存、登录、UI等 | 不归入本次提示词效果；沿用 main 现有实现，不能声称通过改提示词解决了请求故障 |

法律与安全文本作为完整前缀保留，表达层追加其后。虽然原文未变，附加提示仍可能影响生成行为，后续产品测评应继续覆盖法律问句。普通多轮一致性规则也不能替代法律内容准确性的验证。

## 接入与验证

- 网页同伴对话调用 `getCompanionChatPrompt`，使用原有案例匹配、SOP检索与安全说明，再追加表达层。
- 嘉宾对话继续使用原有完整提示词；DeepSeek请求格式、思考流与输出审核不变。
- `bun run test:prompts` 检查普通问题和11组法律Golden问题的原有完整提示词均逐字保留，并校验表达配置边界。
- `bun run test:deepseek` 验证实际接口发给模拟上游的同伴提示词已更新，嘉宾提示词保持原样，并检查原有流式行为。
- 原有安全护栏、SOP检索与法律离线Golden回归继续执行。

离线测试证明接入与保护边界，没有证明真实模型回复质量已提高；此前Claude实测因缺少服务端密钥未运行，本次移入main也不包含真实DeepSeek效果评估或部署。

本次验证结果：提示词保护13项、安全护栏50项、SOP检索18项、法律离线Golden 23项、DeepSeek模拟接口16项，共120项通过；11项法律在线测试未启用。TypeScript、改动文件ESLint与Git差异格式检查通过。与移入前main比较，法律材料、原有提示词组成、检索和安全代码均无修改。
